# Отчёты канала УЗП для DataLab

Код пишется в открытом контуре на синтетике, исполняется в закрытом контуре
DataLab на пром-данных. Схема и имена таблиц локально повторяют промышленные
точь-в-точь, поэтому SQL переносится без правок.

## Отчёты

| Тетрадка | Что считает | Пакет |
|---|---|---|
| `run_tasks.ipynb` | Эффективность отработки задач воронки: привлечение, расширение, запуск, активация. Результат, дисциплина, признаки формальных закрытий. HTML-дэшборд с выбором ТБ. | `uzp_tasks/`, методика — `methodology_tasks.md` |
| `flow.ipynb` | Переток получателей ЗП между организациями год к году. | `uzp_flow/`, методика — `methodology.md` |

## Открытый контур: синтетика

```bash
docker start uzp_pg              # docker compose здесь не работает
python3 -m synth_tasks           # синтетика по профилю витрины задач
python3 -m synth_tasks.verify    # проверка: ловит ли аналитика заложенные архетипы
python3 -c "import uzp_tasks; uzp_tasks.run(report_month='2026-08')"
```

Профили промышленных витрин (структура и статистика, без данных) —
в `data/profiles/`. Результаты — в `output/`.

`synth/` — генератор синтетики прежнего отчёта (`uzp_dash`); в этом
репозитории он неработоспособен: импортирует отсутствующий пакет `uzp_dash`.
